>[!info] Snort Basics
>Snort ist ein Open-Source-IDS, mit dem Echtzeit-Paketanalysen in IP-Netzwerken durchgeführt werden können. Mit Snort können Angriffe wie Pufferoverflow, Stealth-Port-Scans, CGI-Angriffe (Common Gateway Interface), SMB-Tests (Server Message Block), OS-Fingerprinting-Versuche und vieles mehr erkannt werden. Snort kann für verschiedene Arbeitsweisen konfiguriert werden:
>- A) Sniffer Mode (Monitor Mode)
>- B) Packet Logger (Monitor Mode)
>- C) Network Intrusion Detection (Monitor Mode)
>- D) Network Intrusion Prevention (Inline Mode)

>[!tip] Regeln: 
>
> Rules werden durch bekannte Angriffssignaturen erstellt und in der Konfigurationsdatei `snort.conf` abgelegt.
> Sie bestehen aus einem **Rule Header** und **Rule Options**:
>- Der Rule Header enthält Informationen darüber welche Aktion eine Regel ausführt. Es enthält auch Kriterien für den Abgleich einer Regel mit Datenpaketen.

>Monitor Mode Action:
>- `alert` - Generiere einen Alert, nach der in der .conf festgelegten Alert Methode und Log-Eintrag für das Paket.
>- `log`- log-Eintrag für das Paket
>- `pass` - Ignoriere das Paket
>- `activate` - Alert und dann einer andere Regel aktivieren
>- `dynamic` - Bleibe solange idle bis von einer activate rule aktiviert
>
> Inline Mode Action:
>- `drop`- blocke und Log-Eintrag für das Paket
>- `reject` - blocke das Paket, Loge-Eintrag und dann sende ein TCP, RST, wenn TCP bzw. ein ICMP port unreachable bzw. UDP Port unreachable
>- `sdrop` - blocke das Paket ohne Log-Eintrag
>
>Protocol:
>kann TCP, UDP, ICMP oder IP lauten, wenn IP oder ICMP wird im folgenden die Port Angabe ignoriert. Ein Eintrag muss jedoch existieren, z.B any.
>
>Definition von Variablen:
>- var RULES_PATH/snort/rules/
>- portvar HOME_PORTS [22,80,1024:1050]
>- ipvar HOME_NET [192.168.1.0/24, 10.1.1.0/24]
>
>Benutzung von Variablen:
>- `alert tcp any any -> $HOME_NET $HOME_PORTS` (msg:"SYN packet";)
>- include $RULE_PATH/example.rule
>
>Jedes Feld kann mit Variablen gefüllt werden, die zuvor definiert werden. Der Zugriff erfolgt über $VARIABLE. Bei der Definition wird das Dollar-Zeichen jedoch weggelassen.
>
>In Snort können drei Arten von Variablen definiert werden:
>- var, portvar, ipvar

>[!info] Beispiel Regeln:
>- Im Body braucht jede Regel eine eindeutige ID (sid) mit der Snort die Regel referenzieren kann.
>- Jede Regel braucht einen classtype anhand von dem Snort die Regeln priorisieren kann.  
>- Für unser Beispiel soll noch eine Nachricht ausgegeben werden mit msg.
>- ICMP Type auswerten (Redirects sind ICMP Typ 5) mit icode
>
>**fertige Regel:**
>```bash
>alert icmp any any -> any any (sid:15; msg:"ICMP Redirect Detectet"; icode:5; classtype:icmp-event;)
>```
>![[Pasted image 20260206170420.png | 560]]
>
>Rule Options werden in vier Kategorien geteilt:
>- Genaral Options
>	- beschreiben die Regeln, berühren aber nicht die detection
>>[!example]
>>- msg: Beschreibt wie der Log-Eintrag aussieht
>>- reference: Erlaubt es fremde IDS mit einzubeziehen (wie Antivirus oder Nessus)
>>- gid: Das gid Keyword (generator id) gibt an, welcher Teil von Snort die Regel ausgelöst hat (Ruse system: gid = 1)
>>- sid: Eindeutige ID der Snort Regel
>>- rev: Keyword um Revisionen von Regeln zu identifizieren.
>>- classtype: Keyword das eine Klasse von Angriffen bezeichnet
>>- priority: Priorität der Regel
>>- metadata: Für Zusatzinformationen über die Regel
>
>- Payload Options
>	- Regeln, die sich auf Paket-Inhalte beziehen
>>[!example]
>>- **content**: Definiert einen bestimmten Inhalt auf dem Snort den Payload filtert
>>- **rawbytes**: Der Payload wird raw ausgewertet, ohne, dass dieser durch einen Präprozessor dekodiert wurde
>>- **depth**: Wie viele Bytes des Payloads sollen ausgewertet werden?
>>- **offset**: Wo soll mit der Suche begonnen werden?
>>- **distance**: Wie viel Abstand darf zwischen zwei Ausdrücken liegen
>>- *within*: Wie viel Abstand darf maximal zwischen zwei Ausdrücken liegen?
>>- **uricontent**: Normalisiert URIs
>>- **isdataat**: Keyword muss an einer bestimmten Position liegen
>>- **pcre**: Regel ist in PCRE (Perl Compatible Regular Expressions) ausgedrückt
>>
>>```bash
>>alert tcp any any -> 192.168.1.0/24 111 (content:"ABCD";)
>>#content findet statische Pattern in Netzwerk Daten.
>>```
>>
>>```bash
>>alert tcp any any -> 192.168.1.0/24 111 (content:"ABCD"; offset:2;)
>>#skip 2 bytes before searching for "ABCD"
>>```
>>
>>```bash
>>alert tcp any any -> 192.168.1.0/24 111 (content:"ABC"; content:!"EFG"; within:10;)
>>#make sure "EFG" ist nicht within 10 bytes of "ABC"
>>```
>>
>>```bash
>>alert tcp any any -> 192.168.1.0/24 111 (content:"index.php"; http_uri)
>>#match index.php in the http_uri
>>```
>
>- Non-Payload Options
>	- Regeln, die sich auf die Header beziehen
>- Post-Detection Options
>	- Trigger, die Auswirkungen haben, nachdem eine Regel ausgelöst wurde 
>
>>[!example] Gewünscht ist eine Regel, die HTTP Basic Authentizierung erkennt und warnt. Weil Username/Passwort unverschlüsselt übertragen werden.
>>```bash
>>alert tcp any any -> any 80 (msg:"Cleartext authentication Detected"; sid:16; classtype:string-detect; flow:to_server,established; content:"Authorization:Basic"; nocase;)
>>```

>[!abstract] Positionierung von Snort als IDS :
>- im Monitor Mode hinter Firewall:
>
>![[Pasted image 20250122140723.png]]
>
>IDS kann nicht jeden Angriff erkennen, da einige Teile der zum Angriff gehörenden Pakete von der Firewall blockiert werden. IDS kann daher die Signatur des Angriffs nicht vollständig erkennen.
>
>- Im Monitor Mode vor der firewall
>
>![[Pasted image 20250122140905.png]]
>
>IDS überwacht alle Angriffe von außen. Somit ist es möglich, Signaturen der Angriffe zu erkennen.

>[!abstract] Positionierung als IPS:
>- im Inline Mode -> direkter Eingriff in den Datenverkehr:
>
>Snort überwacht allen Netzwerkverkehr und wird auf Grund der eingetragenen Snort Rules Datenverkehr blockieren.
>

#### Snort Architektur:
>[!info] Snort Knomponenten: 
>- **Packet Decoder/Sniffer:** Bereitet Pakete für die Verarbeitung vor.
>- **Präprozessoren:** (1) Daten für die Detection Engine vorbereiten; (2) Erkennung von Anomalien in Paket-Headern; (3) Paket Defragmentierung, (4) Decodes HTTP URI; (5) Zusammenbau von TCP-Streams.
>- **Detection Engine:** Wichtigster Part. Wendet Regeln auf Pakete an.
>- **Log- und Alertsystem:** Erzeugt Warn- und Protokollnachrichten.
>- **Ausgabemodule:** Verarbeitet Warnungen und Logs und generiert die endgültige Ausgabe.
